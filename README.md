# FrameCheck

把通信解析器“偶尔丢一帧”的问题，保存成修复后可以重复验证的测试。

当前版本：**0.3.1，开发预览版**。已完成本地回归与一块 STM32 板卡的项目级实测，仍需更多真实项目验证。详见 [验证记录与限制](docs/validation.md) 和 [更新记录](CHANGELOG.md)。

FrameCheck 面向嵌入式和机器人工程师，包含 Codex 引导技能与本地测试工具。Codex 帮你找解析代码、确认协议中的关键规则、生成测试接入文件；工具负责输入分包数据、比较预期消息与实际消息，生成中文报告和可以重跑的失败用例。支持 Python，以及通过宿主动态库接入的 C/C++ 解析器。

## 最容易的开始方式

在 Codex 中打开你的项目，加载 FrameCheck 后直接说：

> 帮我检查当前项目的串口解析器。先找相关代码，再引导我补充缺少的信息。

也可以指定项目：

> 用 FrameCheck 检查 `D:\projects\my-robot` 的通信解析器，只读取这个目录。先告诉我找到了哪些文件。

不需要先手写完整协议文档或测试用例。引导流程会：

1. 在你指定的项目范围内寻找接收入口、解析函数、帧结构、编码函数和 CRC／校验函数，列出文件位置与依据。
2. 读取相关代码；遇到代码无法证明的协议规则时，只询问影响下一步的缺项。例如 CRC 覆盖范围、字节序、错误帧后的处理方式。
3. 根据已确认的规则生成适配器和用例，在宿主环境运行，展示失败时的输入与输出。默认将接入文件放入单独目录，保留原解析代码。

如果项目不在 Codex 可读取的位置，可以从解析函数开始粘贴。插件会继续指出需要哪个头文件、常量或校验函数，不要求一开始上传整个工程。完整过程与命令行方式见 [新手接入指南](docs/getting-started.md)；插件加载方法见 [安装说明](docs/install.md)。

代码表现只能说明实现怎样工作，不能独立证明协议本来应该怎样工作。预期消息需要协议说明、人工确认的正确报文或独立实现支持；不确定的部分会保留为待确认项。

## 可选：先检查接板信息

`board-info`：先列出下载器和串口，再在明确选择下载器及支持的读取配置后，读取芯片元信息。它帮助接入和排查连接；协议规则仍由项目依据与用户确认。需要独立的可选板卡工具环境，见 [接板信息入口](docs/board-intake.md)。下载源码不会自动更新已安装插件。

## 可选：用自己的规则验收真实串口

`serial-run` 支持项目自定义的串口验收。插件根据项目依据准备发送内容、预期回包与观察窗口；离线自检与真实串口明确分开。真实执行需要显式指定端口，不自动复位或烧录。工具不固定 CRLF、回显、199 字节或板卡型号，见 [串口验收入口](docs/serial-exchanges.md)。

## 先看一个能跑的演示

需要 Python 3.10 或更高版本。在源码根目录运行；宿主 Python 演示仅使用标准库，无须 API 密钥；可选串口和板卡功能需要另外安装依赖。

```console
python --version
python -m framecheck demo --out ./demo-output
```

打开 `demo-output/index.html`，查看正确解析器和四个故障版本的比较。演示包含完整帧、任意切点分包、逐字节输入、连续多帧、空载荷、最大载荷、CRC 损坏和噪声后恢复。

正确版本应通过；四个故障版本分别演示分包丢数据、连续帧漏收、跳过 CRC 和噪声恢复失败。演示命令返回 `0` 表示这些预设检查符合预期，因此故障版本出现失败是演示成功的一部分。这证明工具能检出这些已知缺陷，不代表对任意协议的缺陷发现率。

## 报告和再次验证

每次测试生成：

| 文件 | 用途 |
| --- | --- |
| `report.html` | 查看失败原因、每次输入的字节分块、预期与实际消息 |
| `report.json` | 自动处理与持续集成 |
| `repros/<case-id>.json` | 保存失败时的原始分块和预期，供修复后再次运行 |

可以让 Codex“重放这份失败用例，检查刚才的修复”，也可以独立运行 CLI。执行、重放和自定义协议的命令见 [新手接入指南](docs/getting-started.md#命令行方式)。

## 当前边界

- 宿主解析器测试输入来自本地用例，不打开串口、不操作设备、不烧录固件。可选 `board-info` 会枚举设备，显式连接时读取限定芯片元信息，不请求复位、暂停、解锁或烧录；其 SDK 可能改变调试寄存器。命令不自动下载依赖或设备包。
- 可选 `serial-run --live` 会打开明确指定的端口并发送项目用例，记录真实回包；离线自检不操作硬件。该入口不请求复位、暂停、解锁或烧录。
- 项目检索帮助定位代码，不能自动证明协议规则或解析器正确。STM32 HAL、RTOS、DMA 等依赖可能需要宿主包装或替身；不能直接编译时会说明缺少什么。
- 宿主解析器验收的每个用例在单独的子进程中执行，并限制运行时间。该机制用于回收卡住的测试进程，**不是安全沙箱**；只运行你信任的适配器和动态库。
- 宿主解析器测试覆盖宿主环境下的消息输出；MCU 上的中断、DMA、内存限制、串口时序、电气问题，以及真实设备的表现仍需实测。
- 宿主解析器用例的分块序列不包含时间间隔。超时、序号去重和协议状态机规则需要明确约定并另行接入，不能从字节分块推断。
- 本地检索脚本只读项目文件。Codex 读取的代码片段、用例和报告可能进入模型上下文；本地测试核心不等于整个 Codex 对话离线。请只授权读取你允许用于该服务的项目范围。

FrameCheck 聚焦语义验收和固定失败用例，不声称首创串口回放或模糊测试。已有工具包括 [OpenBaud](https://github.com/Leonezz/openbaud) 和 [BaudOwl](https://github.com/iotsrg/baudowl)。
