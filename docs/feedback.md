# 按项目输出具体问题反馈

宿主 `run`、`replay` 和 `demo` 的失败结果现在包含 `feedback`；通过结果为 `null`。HTML 报告展示“问题反馈”、建议及可展开的定位证据，JSON 和失败复现文件保留同一份信息。旧版报告仍可展示。串口验收和项目检索仍使用各自现有报告，本次没有改动它们。

## 消息输出不同

例如某项目独立确认的预期为 `{"axes": [{"enabled": true}]}`，实际为 `{"axes": [{"enabled": 1}]}`。反馈会指出第几条消息、字段路径 `["axes", 0, "enabled"]`，并说明预期 `boolean`、实际 `number`。

字段名由项目决定，不要求 `axes`、CRC、帧头或特定结束符。路径是相对于单条消息的字段名／数组索引列表，JSON 中的消息和数组索引从 0 开始；页面文字从第 1 条／第 1 块开始计数。特殊字符和空字段名也作为普通路径项保存。

- 区分缺少／多出消息、字段和数组项，以及值或类型不同；缺项与 JSON `null` 分开记录。
- 定位第一条不同消息内的首个差异。对象按预期字段顺序检查，再检查多出的实际字段；数组按索引检查。这不是全部差异清单。
- 对象字段顺序不影响比较，数组和消息顺序影响比较；数字 `1` 与 `1.0` 相等，布尔值 `true` 与数字 `1` 不相等。
- 字符串只显示有限预览，对象／数组显示大小；完整数据仍在预期与实际输出中。

建议先核对独立协议依据，再检查适配器映射与解析状态。一个字段不同不能直接证明 CRC、字节序或分包逻辑有错，也不触发自动修改用户协议。

## 运行未完成

Python 异常会记录加载／创建、reset、feed 或输出格式检查阶段，以及已知的分块索引、异常类型和最内层 Python 调用位置。位置只包含文件名、行号、函数名，不包含局部变量或源码；同名文件需要用户结合自己的工程辨认。C 库经 Python 包装报错时，该位置可能只指向包装层，不代表原生 C 故障行。

异常前已通过格式检查的输出会保留，页面标为“已记录输出（运行未完成）”；即便它碰巧等于预期，状态仍是 `error`。触发格式错误的那次输出不并入已记录输出。超时、崩溃或进程直接退出时没有内部进度证据，阶段和分块保持未知，不推测故障位置。

每次宿主执行使用新的、不写入的 Python 字节码缓存位置，避免同一秒内等长修改或已有模块缓存让重放继续运行旧源码。该设置覆盖本次解释器导入；不控制用户自建子进程、原生库内部缓存或运行期间自行修改源码的行为。

## 修复闭环与边界

复现文件保存原始输入分块、独立预期和当时反馈。重放会重新执行并重新生成反馈，不把旧反馈当作本次结果。修改预期应有协议依据，不能为消除失败而迎合实际输出。

这里比较的是用例结束时的有序 JSON 消息，不断言消息应在哪次 `feed` 发出，不模拟中断、DMA、真实串口时间或内存安全，也不自动判断用户的业务规则。
